## 為什麼做

既有之 `iso_27090_overview.html` 雖然已建立基礎架構，但為達最高品質與嚴謹標準，需進一步深化：
1. **發行日期需極度嚴謹考據**：嚴格界定 ISO 官方 Stage 60.00（Under Publication）之狀態定義，釐清 ISO 官方僅標註年月（2026-10）而無特定「日」之出版機制，避免時間資訊誤導。
2. **視覺體驗升級**：目前全依賴純文字與 Mermaid 代碼，需運用 `codex exec`（搭配 `codex_imagegen.py`）產出多張高畫質繁體中文 AI 資訊圖表（16:9 與直式響應），大幅提升可讀性與視覺吸引力。
3. **引入雙頂尖模型交叉審查機制**：
   - 透過 **Claude Code** 最佳模型進行「內容深度與因果嚴謹度審查」及「UI/UX（Claude Design 美學、排版節奏、直屏閱讀）審查」。
   - 透過 **Codex Exec** 最佳模型進行「AI 資安威脅模型完備度與標準技術結構審查」。
   - 依據兩大頂尖模型審查反饋，全面重構與潤飾 HTML 網頁。

## 要改什麼

- **日期考據嚴謹化**：修正並加註 ISO/IEC JTC 1 國際標準出版流程（DIS 2025-04 -> FDIS 2026-03~08 -> Stage 60.00 2026-10 出版排程）之官方真實規則。
- **AI 資訊圖表生成與整合**：
  - 調用 `codex_imagegen.py` 生成 2~3 張 16:9 核心視覺圖（歷程圖、治理三角圖、五大威脅全景圖），並儲存於 `images/` 目錄。
  - 將圖表優雅嵌入 HTML，搭配圖說與自適應樣式。
- **多模型交叉審查執行**：
  - 調用 `claude -p` 針對 HTML 進行「資安專業內容」與「UI/視覺排版」兩階段評審。
  - 調用 `codex exec` 針對 HTML 進行「標準與攻擊向量技術完整性」評審。
  - 產出審查報告與修訂清單。
- **HTML 與樣式全面迭代升級**：
  - 根據審查結論重構 HTML，注入更高質感的 UI 設計（精緻陰影、字體間距、圖文並茂、響應式優化）。
